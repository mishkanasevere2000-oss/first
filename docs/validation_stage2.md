# Проверки этапа 2 — первый банковский PDF

Статус: этап 2 завершён. Реализация 0.3.0 проверена в Linux, пользователь
подтвердил проверки на Windows. Схема SQLite осталась версии 1.

## Объём и изменение первого формата

По согласованию в беседе первым источником выбран PDF вместо первоначально
предложенного XLSX. PDF предусмотрен ТЗ v1.1 и Архитектурой v1.0. Поддержан
один формат кредитной карты Сбера; другие форматы не объявляются готовыми.

Добавлены models, detector, sber_credit_pdf_v1, service, CLI импортера и сценарий
пункта 1 основного меню. Добавлена библиотека pypdf 6.20.1. В Store выделена общая
валидация одной операции и добавлена пакетная запись проверенного первого файла
одной транзакцией. Миграции схемы и изменения финансовой модели не потребовались.

В репозитории — только вымышленные TXT/PDF-примеры. Исходный PDF пользователя,
его текст, реальные операции и созданные для сверки базы не публикуются.

## Автоматические проверки

Linux, Python 3.12.14. Выполнено:

```sh
.venv/bin/python -m pip install --no-cache-dir pypdf==6.20.1
.venv/bin/python -m pip check
.venv/bin/python -m pytest -q
```

Результат полного pytest после последних изменений: **119 passed**.
`pip check`: No broken requirements found.

Проверены:

- Извлечение текста из реального синтетического многостраничного PDF через pypdf.
- Точные копейки, оба направления, остатки, переносы описаний, сохранение
  исходных строк описания и нормализация межсловных пробелов в description.
- Раздельные даты: операция июля с обработкой августа не становится августовской.
- Две одинаковые покупки остаются двумя записями.
- Отказ при неизвестном формате, скане/пустом PDF, пароле, повреждённых данных,
  неверных датах/времени/обязательных строках и нарушенной нумерации страниц.
- Несходящиеся обороты блокируют импорт; расхождение формулы остатка явно
  предупреждается, исходные значения не исправляются.
- Все банковские поля, происхождение, служебная запись импорта и аудит
  сохраняются; классификации, категории, правила и связи не создаются.
- Предпросмотр/отмена не создают базу и не записывают операции.
- CLI требует подтверждение; меню показывает предпросмотр и ожидает `ДА`.
- Ошибка SQL посередине записи откатывает imports/operations/audit целиком.
- Повторная попытка в непустую базу отвергается без изменения её файла.
- Исходный PDF после импорта не изменён и не перемещён.
- Регрессионные проверки этапа 1 и обновлённые smoke-тесты пройдены.

## Сверка исходного PDF пользователя

Реальный источник проверен отдельно от публичного синтетического набора:

1. Обработчик прочитал все страницы и все строки.
2. Количество строк сверено со всеми видимыми началами операций при независимом
   извлечении через Poppler `pdftotext -layout`.
3. По всем строкам независимо сравнены дата, время, processing_date, код
   авторизации, сумма, направление, остаток и описание с переносами.
4. Описания сравнивались с нормализацией межсловных пробелов; исходные строки
   pypdf дополнительно сохранены в source_data. Числовые значения не округлялись.
5. Суммы IN/OUT отдельно совпали с банковской шапкой.
6. В исходнике есть несходящийся конечный остаток шапки. Это отражено в
   предупреждении; утверждение о согласованности всех остатков не делается.
7. CLI preview и import --confirm выполнены на временной отдельной базе.
   Программа вывела предупреждение и маскированный номер счёта.
8. После записи все операции и поля совпали с результатом чтения; проверка
   структуры/целостности прошла, classifications осталась пустой.
9. Временная база удалена, исходный PDF сохранён без изменений. Рабочая пустая
   finance.db проекта реальными операциями в ходе этой проверки не заполнялась.

В целях приватности реальные реквизиты, описания, суммы и извлечённый текст
в этом общедоступном протоколе не приводятся.

## Выполненный порядок проверки на Windows

1. Скачать версию 0.3.0 в новую папку; старую установку и finance.db не заменять.
2. Создать .venv, установить requirements, выполнить pytest: ожидаются 119 passed.
3. Явно создать новую пустую базу (`program.database init`) и проверить её.
4. Скопировать поддерживаемый PDF в input, запустить BAT, выбрать 1.
5. Проверить число строк, банковские обороты и предупреждение. Ответом, отличным
   от `ДА`, можно проверить отмену без записи; затем повторить предпросмотр.
6. Подтвердить `ДА`, проверить сообщение о записи и `program.database check`.
7. Убедиться, что повторная попытка отказана, а исходный PDF остался в input.

Результаты получены от пользователя и записаны ниже; они не подменяются Linux-прогоном.

## Ограничения

Нет OCR, остальных банков/форматов, дедупликации, автоматического архивирования,
расчёта реальных доходов/расходов, классификации и финансового отчёта.
Первый импорт работает только в пустую базу. Банковский код авторизации не
используется как уникальный transaction ID. Полная защита повторных и
перекрывающихся выписок и расширенная история импортов — этап 3.
