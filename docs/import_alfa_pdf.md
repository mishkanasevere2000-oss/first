# Альфа-Банк — выписки счетов, программы 0.10.0–0.10.1

Шестая часть этапа 4: рублёвая «Выписка по счету» с номером счёта, периодом,
входящим/исходящим остатками, поступлениями/расходами и таблицей «Дата проводки / Код
операции / Описание / Сумма в валюте счета». RUR принимается как рубль.
Распознавание по содержимому и банковскому колонтитулу, не имени файла.
Сканы, другие валюты и иные формы пока не поддерживаются.

## Даты и факты — существенные различия источника

- Дата проводки сохраняется в processing_date. Для карточной строки CRD_ дата
  совершения извлекается из описания в operation_date. Двузначный год принимается
  только как год проводки или предыдущий календарный год; более старые либо
  неоднозначные даты запрещают запись. Покупка позже проводки запрещена.
- Для переводов отдельная дата совершения не указана. В обязательное поле
  operation_date записывается дата проводки с явной пометкой
  source_data.operation_date_source=POSTING_DATE; это дата банковской записи,
  не подтверждённая независимая дата совершения. Для карточной даты пометка
  DESCRIPTION. Ограничение отображается до подтверждения и после импорта.
  Будущий финансовый движок должен учитывать источник даты.
- Время отсутствует: operation_time_local=NULL, не выдуманные 00:00.
  Остатков после отдельных операций нет: NULL. Часовой пояс не угадывается.
- Карточное описание сохраняется полностью. Из него отдельно извлекаются
  маска карты и фактический четырёхзначный MCC; сумма в описании должна
  совпасть по модулю с суммой проводки, валюта должна быть RUR. MCC не превращается
  автоматически в категорию пользователя. Иные варианты карточного описания
  и неоднозначные/неверные поля останавливают импорт.
- Код операции сохраняется в source_data.bank_operation_code. Он НЕ уникален:
  в предоставленной выписке один CRD-код повторяется у покупки и возврата,
  есть и частичный CRD_. bank_transaction_id остаётся NULL. Код — именованная
  часть комбинации признаков, а не самостоятельный ключ; разные события
  с одинаковым кодом не объединяются. Одинаковые вхождения сохраняются по числу.
- Положительная сумма — IN, отрицательная — OUT; копейки целые, без float.
  Суммы строк обязательно совпадают с поступлениями и расходами банка,
  входящий остаток + обороты — с исходящим. Иначе запись запрещена.
- Проводка должна входить в период. Покупки до периода сохраняются с обеими
  датами и предупреждением. Текущий баланс на дату формирования не подменяет
  остаток на конец периода. Категории, доходы/расходы и связи не назначаются.

## Нумерация PDF и совместимость

В образце номера страниц находятся во вложенных Form XObject без собственных
шрифтовых ресурсов. Обычное извлечение pypdf пропускает этот текст. Для этого
формата дополнительно читаются только формы, вызванные Do на конкретной странице,
с ресурсами шрифтов страницы. Используется временная копия объекта, сам PDF
не меняется. Невызванные формы с номерами других страниц игнорируются.
Нумерация «Страница N из M» обязательна и должна совпадать с полным документом.

Общий накопительный импорт и архив: archive/statements/ГОД/alfabank/SHA256.pdf.
Схема SQLite остаётся 2. Код операции и источник даты хранятся в существующем JSON,
в модели PDF добавлены необязательные поля; прежние парсеры и отпечатки операций
без кода не меняются. Обновление: новая папка, copy прежней базы, перенос archive,
check/info; старую установку сохранить. Команды в README. Обычный импорт — копия
в input → BAT → пункт 1 → просмотр → ДА.

## Коды с внутренним # — 0.10.1

В предоставленной кредитной выписке код выдачи/погашения транша содержит
разделитель # и повторяется в разных событиях. Теперь допускается один
внутренний # между непустыми буквенно-цифровыми/подчёркнутыми частями кода.
Например, вымышленный MG01#TEST. Ведущий, завершающий или двойной # по-прежнему
отклоняется. Код не превращается в уникальный банковский ID; остальные проверки
и признаки идентичности не меняются. Схема остаётся 2, alfa_account_pdf v1.
