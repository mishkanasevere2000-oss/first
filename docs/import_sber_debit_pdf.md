# Дебетовая карта Сбера — текстовый PDF, программа 0.6.0

Вторая часть этапа 4: рублёвая «Выписка по счёту дебетовой карты», оформленная
в СберБанк Онлайн. Формат определяется по содержимому, не имени файла.
Сканы, другие валюты и иные варианты оформления пока не поддерживаются.

## Разбор и сохранение

Используется тот же строгий разбор пар строк Сбера, что для кредитной карты,
но с отдельными названием, parser_name=sber_debit_pdf v1 и заголовком
«СУММА В ВАЛЮТЕ СЧЁТА». Дополнительные подзаголовки и номера сносок 1/2
допускаются только до начала операций страницы. Исходные номера строк
не меняются: текст перед разбором не переписывается в кредитный формат.

Сохраняются обе даты (совершения и обработки), время МСК, шестизначный код
авторизации, полное описание с переносами, сумма в копейках, направление
и банковский остаток после операции. Код авторизации не объявляется
уникальным ID: используется существующее сопоставление по признакам
с сохранением количества одинаковых покупок. Счета разделены по номеру,
даже когда обе выписки относятся к Сбербанку.

Знак плюс означает пополнение, сумма без плюса — списание. Суммы всех строк
обязательно сверяются с отдельными итогами пополнений/списаний в шапке.
При расхождении запись запрещена. Остатки сверяются; как и для кредитного
формата, несходящийся конечный остаток сохраняется с предупреждением.
Дата совершения вне периода не отбрасывается: банк отбирает обработанные
операции, обе даты сохраняются отдельно. Пропущенные страницы, неверные
даты/суммы/код, неподдерживаемые строки таблицы запрещают запись.

Категории банка не превращаются в финансовые категории пользователя.
Переводы, зарплата и иные аналитические значения автоматически не назначаются.

## Совместимость и запуск

SQLite-схема остаётся 2. Для обновления в отдельную папку сначала перенести
существующую базу командой database copy и папку archive целиком. Старую
установку сохранить. Последовательность установки и проверки — в README.

PDF скопировать в input → BAT → пункт 1 → просмотр → ДА. После успешной
записи источник переносится только после проверки архива:
archive/statements/ГОД/sberbank/SHA256.pdf. Журнал попыток, восстановление
архива и защита от повторов общие с прежними форматами.

## Проверки разработчиком

- Полный набор: 178 passed в Linux с закреплёнными зависимостями.
- 16 новых проверок: настоящее извлечение вымышленного двухстраничного PDF,
  обнаружение и различение форматов, подзаголовки/сноски, перенос описания,
  обе даты, одинаковые покупки с одинаковым кодом, повреждённые строки,
  неполный PDF, предупреждение об остатке, короткая → полная выписка,
  повтор по тому же и другому SHA, смешанный импорт трёх форматов.
- Настоящий пользовательский PDF проверен вне репозитория: 42 операции,
  14 пополнений / 381 167,02 ₽, 28 списаний / 376 048,14 ₽; начальный остаток
  0,00 ₽, конечный 5 118,88 ₽, всё сходится.
- Независимое извлечение Poppler сверено по всем 42 строкам с pypdf: обе даты,
  время, код авторизации, описание, сумма, направление, остаток совпали.
- Во временной базе прежние настоящие файлы дают 251 операцию. Дебетовая
  выписка добавляет 42; повтор того же и заново записанного PDF даёт
  0 новых / 42 известных. Итог 293; прежние 251 запись и ID не изменились,
  проверка целостности проходит, классификации не создаются.
- Настоящие PDF, реквизиты, извлечённые тексты и рабочие базы не публикуются.

## Windows-проверка — предстоит

Установка в отдельную папку, pytest; copy прежней базы и перенос archive;
check: схема 2, info: 251 операция. Затем импорт: 42 новых / 0 известных,
повтор: 0 новых / 42 известных. Итог info: 293 операции без FAILED/PENDING.
Результат пользователя будет записан после проверки. Поддержка этих трёх
форматов не означает завершение всего этапа 4 или MVP.
