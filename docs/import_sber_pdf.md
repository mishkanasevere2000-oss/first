# Первый PDF-импорт — версия программы 0.3.0

Поддерживается один текстовый формат: выписка по счёту кредитной карты из
СберБанк Онлайн, обработчик `sber_credit_pdf`, версия `1`. Не все PDF Сбера
имеют такую структуру. Нераспознанный формат не угадывается. OCR отсутствует.

## Что делает программа

- pypdf читает PDF из памяти без внешнего сервиса и без установки Poppler.
- detector проверяет PDF, наличие текста на всех страницах и признаки формата.
- Обработчик проверяет период, рубли, счёт, итоги, заголовки/порядок страниц,
  все строки, даты, знаки сумм, описания с переносами и остатки.
- Деньги переводятся из текстовых чисел прямо в целые копейки; float не используется.
- operation_date и processing_date сохраняются отдельно. Дата в шапке не является
  причиной удалять строки с operation_date вне неё: банковский период может
  определяться датой обработки.
- Положительный знак суммы — IN; сумма без плюса или с минусом — OUT.
- Если суммы строк не совпали с оборотами шапки, запись запрещена.
- Если расходится только формула конечного остатка, программа явно предупреждает,
  но не исправляет банковские остатки. Обороты всё равно обязаны совпасть.
- Перед записью пользователь видит обороты и все предупреждения.

Банковская «КАТЕГОРИЯ» служит только признаком этого табличного формата,
не переносится в аналитическую модель. MCC и выделенный контрагент отсутствуют
в этом образце и остаются NULL, а не угадываются из описания. Код авторизации
сохраняется в source_data, но не становится bank_transaction_id: он не уникален.

При записи создаются imports и operations, а также audit_log. classifications,
ручные решения, правила и связи не создаются. Новая запись не означает, что
пополнение признано доходом, а списание — реальным расходом.

## Безопасный предел этапа 2

Запись разрешается только в **пустую базу**, без imports и operations.
Дедупликация будет реализована на этапе 3. Сейчас отказ от следующей загрузки
защищает от случайного повторного добавления; программа не предлагает стереть
существующие данные ради повторной попытки.

Один импорт — одна SQLite-транзакция, включая служебную запись и аудит.
Все строки валидируются до записи. Ошибка записи откатывает всю транзакцию.
Схема остаётся версии 1; существующие базы 0.2.0 не требуют миграции схемы.

Автоматического архивирования пока нет: исходный PDF остаётся на месте,
на диске его не переименовывают и не удаляют. Полный журнал повторных/ошибочных
импортов и контроль по хешу файла относятся к этапу 3. В случае отказа на этапе 2
служебная «частично успешная» загрузка в базе не остаётся.

## Через обычное меню

1. Подготовить программу в отдельной новой папке, как описано в README.
2. Явно создать пустую базу командой `program.database init`.
3. Скопировать одну поддерживаемую PDF-выписку в input.
4. Запустить BAT и выбрать 1. При отсутствии PDF или наличии нескольких
   программа объяснит требование и ничего не запишет.
5. Проверить предварительные сведения и предупреждения.
6. Для записи ввести `ДА`. Другой ответ отменяет импорт.
7. После успеха выводится число сохранённых операций. Не запускать повторно
   для добавления следующего месяца: эта возможность ещё не реализована.

## Команды разработчика (PowerShell, корень проекта)

```powershell
.\.venv\Scripts\python.exe -m program.importers preview "input\выписка.pdf"
.\.venv\Scripts\python.exe -m program.importers import "input\выписка.pdf" --confirm
.\.venv\Scripts\python.exe -m program.database check
```

Предпросмотр не открывает базу. Для отдельной базы передать `--database ПУТЬ`
команде import. Если база отсутствует, она автоматически не создаётся.
На Linux использовать `.venv/bin/python`.

Технический формат source_row: `page=N;layout_line=M` — номер страницы PDF и
строки извлечённого pypdf layout-текста. source_data хранит исходные строки
описания, время МСК, код авторизации, имя/версию обработчика и банковские
метаданные шапки с предупреждениями. Это позволяет расследовать происхождение
результата, сохранив сам исходный PDF отдельно. Персональные значения остаются
в локальной базе, не в исходном коде и не в общедоступных логах.
