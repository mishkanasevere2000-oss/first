# Проверки этапа 0

Среда проверки: Linux, Python 3.12.14.

Выполнены команды из корня проекта:

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -q
```

Результат: **12 passed**. Проверены импорт, версия, меню, все семь заглушек,
неверный ввод, EOF и запуск отдельного Python-процесса с последующим выходом.
Тесты проверяют отсутствие файловых изменений в рабочем каталоге.
`git check-ignore` подтвердил исключение окружения, logs, output, backup и
рабочей database/finance.db. В Git status они отсутствуют.

## Проверка BAT

Выполнена проверка кода: корень выбирается через `%~dp0`, пути заключены
в кавычки, Python берётся из `.venv`, ошибки сопровождаются сообщением и
`pause`, код завершения приложения сохраняется. Файл записан в UTF-8 с CRLF.

Проверка разработчиком выполнялась на Linux без Windows/cmd.exe.
Затем пользователь выполнил проверки на своём Windows; результаты записаны ниже.

## Ограничения

Финансовые функции отсутствуют по заданию; база данных не создаётся.
Установка окружения выполняется разработчиком по README; BAT не устанавливает
Python или пакеты. На этапе реализации каркаса исходные ТЗ и архитектурные документы ещё
не были предоставлены. Позднее получены ТЗ v1.1, Архитектура v1.0 и План
разработки v1.0; финансовая логика в каркас не добавлялась.

## Исправление по проверке пользователя на Windows

Первый запуск pytest на Windows: 11 passed, 1 failed. Причина — родительский
процесс теста декодировал UTF-8 вывод дочернего процесса в локальной кодировке
Windows. В subprocess.run явно задано encoding="utf-8"; утверждения сохранены.
После исправления в Linux: 12 passed; отдельная проверка test_cli_process
с имитацией кодировки по умолчанию cp1251 также прошла. Результаты повторной проверки на Windows приведены ниже.

Источник: сообщения пользователя в этой беседе. Это выполненные пользователем
проверки, а не запуск Windows на облачном компьютере разработчика.
